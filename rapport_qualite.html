Synthèse

Ce jeu de données présente des risques majeurs pour l'analyse transactionnelle (CA, segmentation) et la modélisation prédictive, avec un score global de 86.4 (note B) masquant des anomalies critiques comme 23.3% de clients non identifiés et 1.17% de doublons identiques. La cohérence des données (69.0) et la validité des prix/quantités (asymétrie extrême à 204.82) compromettent toute analyse fiable. Les annulations (quantités négatives) et les codes de service mélangés aux produits biaisent les calculs de panier moyen et les analyses de performance produit. Une approche par échantillonnage (15%) ne suffit pas à atténuer ces biais systématiques.

Risques principaux

  • Sous-estimation du CA réel due aux annulations non distinguées (quantités négatives) et aux prix extrêmes non validés (ex: -11062.06, 38970.0).
  • Segmentation client erronée : 23.3% des transactions sans identifiant client (C01) fausse les analyses de fidélité et de RFM.
  • Analyses de panier moyen biaisées par les doublons (C04) et les codes de service (C16) mélangés aux produits, faussant les insights merchandising.
  • Modèles prédictifs (churn, demande) contaminés par les descriptions incohérentes (C18) et les espaces parasites (C17), réduisant la précision des recommandations.
  • Perte de traçabilité des transactions critiques (ex: factures hors format C09) et des produits avec descriptions multiples (C19), impactant les audits et les retours clients.

Corriger les quantités négatives (C10) en les flaggant comme des annulations, puis recalculer le CA net en excluant ces lignes. Vérifier les cas extrêmes (ex: -3100) pour détecter des erreurs de saisie ou des fraudes.

Effort faible · Contrôles C10
Les annulations non traitées faussent le CA net et les analyses de performance. Une approche par flagging permet de maintenir l'historique tout en corrigant les calculs. Les cas extrêmes nécessitent une investigation manuelle.
```python
df['Quantity_Corrected'] = df['Quantity'].apply(lambda x: x if x > 0 else 0)
# Flagger les annulations pour analyse ultérieure
df['Is_Cancellation'] = df['Quantity'] < 0
```

Nettoyer les codes de service (C16) en les isolant dans une catégorie dédiée (ex: 'CODE_SERVICE') et en recalculant les agrégats de vente par produit. Documenter les règles de classification pour éviter les réinclusions.

Effort moyen · Contrôles C16
Les codes comme 'DOT' ou 'POST' ne sont pas des produits et doivent être exclus des analyses merchandising. Une catégorie dédiée permettra de suivre les coûts logistiques sans les confondre avec les ventes. Impact direct sur les calculs de marge et de panier moyen.
```python
df['ProductType'] = df['StockCode'].apply(lambda x: 'PRODUIT' if x not in ['DOT', 'POST', 'M', 'C2', 'AMAZONFEE'] else 'CODE_SERVICE')
```

Standardiser les descriptions (C17, C18, C19) en nettoyant les espaces parasites et en normalisant les annotations manuelles (ex: 'Discount' → 'REDUCTION'). Créer un dictionnaire de mapping pour les descriptions multiples d'un même produit (C19).

Effort élevé · Contrôles C17, C18, C19
Les descriptions incohérentes (espaces, annotations) et les doublons (C19) rendent impossible une analyse précise des ventes par produit. Une standardisation permettra de segmenter correctement les données pour les analyses de mix et les prévisions. Effort justifié par l'impact sur la qualité des insights merchandising.
```python
df['Description_Clean'] = df['Description'].str.strip()
# Remplacer les annotations manuelles par des tags standardisés
df['Description_Clean'] = df['Description_Clean'].str.replace(r'\b(Manual|Discount|\?)\b', 'ANNOTATION', case=False)
```

Valider et corriger les prix unitaires extrêmes (C14) en isolant les valeurs aberrantes (ex: > 1000) pour analyse manuelle. Appliquer des règles de nettoyage basées sur les percentiles (ex: exclure les valeurs > P99).

Effort moyen · Contrôles C14
Les prix extrêmes (asymétrie à 204.82) biaisent les calculs de panier moyen et les analyses de rentabilité. Une approche par échantillonnage (15%) ne permet pas de détecter ces outliers. Une validation manuelle ciblée est nécessaire pour éviter de supprimer des données valides (ex: produits premium).
```python
p99_price = df['UnitPrice'].quantile(0.99)
df['UnitPrice_Valid'] = df['UnitPrice'].apply(lambda x: x if x <= p99_price else np.nan)
```
